# Technical Debt Register

Known flaws in `yci`, each with severity, evidence, and a remediation plan.
This file is for **open** items only.

## Scope and lifecycle

- An entry is written when a flaw is *found*, whether or not it is fixed in
  the same change. Never leave a finding in chat only.
- An entry is **deleted** when its work lands, not marked resolved. A register
  of finished items is a work log; `git log` is already that, and keeping a
  second copy only lets the two disagree.
- Numbering is sequential and never reused. A retired number stays retired so
  old references cannot silently start pointing at a different flaw.
- Coverage figures do not belong here. They change every commit and are
  regenerated by `go test -cover`; a stale one is worse than none.
- This file is versioned. `git log docs/` shows what a rule used to say, so a
  rewrite that contradicts an earlier claim is reviewable rather than silent.
- Anything here that describes a design decision or a measurement belongs in
  `docs/<feature>.md` instead.

`TD-01`–`TD-43` are all retired. Their detail was removed rather than
archived: the reasoning that mattered was promoted into `docs/style-guide.md`,
`AGENTS.md` and the feature docs, which is the only reason removing it was
safe.

## Open entries

**TD-45 — a missing staging directory fails the download commands with a raw
path error.** `Enqueue` reads the staging directory to skip videos already
downloaded but not yet imported, and does not create it. On a fresh install
where nothing has made the directory yet, `download <url>` and
`POST /api/v1/queue` both fail with `read staged dir: ... no such file or
directory` instead of creating it. Severity: low, and it is a confusing
first-run failure rather than data loss. The library directory is created at
boot and the staging directory is not. Remediation: create it in the container
boot beside the library one.

## Deferred by decision, not oversight

These are not open work. They are recorded so they are not rediscovered as
mistakes.

**Kanji and romanized aliases do not unify.** `星街すいせい` and
`Mori Calliope` remain distinct to fragment matching. Deferred by decision:
matching is deliberately lexical rather than full work identity, and
MusicBrainz was withdrawn because it splits the pair that motivated it. A
user-curated local alias table is the right shape if it is ever reopened.

**`ytDlp` itself is untested.** The two `exec.CommandContext` calls that
invoke yt-dlp need a real toolchain. Everything around them is covered by the
`Downloader` and `PlaylistFetcher` seams; what remains is a thin wrapper whose
value is in its argument construction, which *is* tested.

**Dynamic playlists remain rejected.** The reasoning, and the conditions that
would reopen the question, are in `docs/playlists.md`. Not a debt item.
